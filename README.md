# 园区访客车辆临时通行系统

被访单位为访客车辆申请临时通行（车牌、预计到离时间、访问楼栋、联系人），门岗核对后放行，
离场按批准时段结算超时费用。零第三方依赖，使用 Node.js 内置 `http` 与 `node:sqlite`（Node ≥ 22）。

## 一条本地命令启动

```bash
npm run seed     # 可选：写入演示数据（在园车辆、跨夜超时车、同车牌多邀请、离线演示邀请）
npm start        # 启动：http://localhost:8080 （PGV_PORT=xxxx 可改端口）
npm run demo     # 离线排队→重放的独立样例（临时库，不污染正式数据）
npm test         # 18 个测试：码防重 / 跨夜计费 / 重复回执 / 单位隔离 / 异常复核
npm run reset    # 清空本地数据库与遮罩照片
```

## 六个页面

| 页面 | 说明 |
| --- | --- |
| `/` 邀请 | 被访单位填写车牌、预计到离、楼栋、联系人，生成 6 位通行码；同车牌可有多份邀请 |
| `/gate` 门岗核验 | **大号车牌 + 批准时段**突出显示；展示同车牌其他邀请；车证相符后放行入场/离场结算 |
| `/inpark` 在园车辆 | 遮罩抓拍照片、批准截止、**剩余时间/已超时** |
| `/billing` 超时计费 | 每张回执**清楚拆分免费时间与超时金额**；模拟支付、支付后闸机故障重试 |
| `/exceptions` 异常放行 | 所有异常处置记录，**异常理由以完整文字显示**；免费放行须园区管理员复核 |
| `/payments` 收费流水 | 支付流水、闸机动作日志、离线队列与一键重放 |

## 业务规则

- **一邀一入**：一张邀请只有一次有效入场；通行码转发再次扫码被拒绝并留处置记录（`exception_releases` + 闸机 `denied` 日志）。
- **出场回执幂等**：门岗重试只返回原回执，绝不重复收费；支付以 `request_id` 幂等。
- **支付后闸机未开**：回执已置为已支付，重试只重新发开闸指令，不二次扣款（收费页有“模拟支付后闸机未开”按钮）。
- **单位隔离**：被访单位只能查看/修改/取消本单位邀请，越权返回 400 并写审计日志。
- **异常免费放行**：门岗/单位登记后为待复核，园区管理员（`admin-1 王主任`）核准后才补事件、开零元回执、开闸。
- **同车牌多份邀请**：允许，门岗核验时并列展示，互不影响各自的一次入场规则。

### 计费拆分

出场结算时拆分为：

1. 批准时段内停留 —— 免费；
2. 提前到达免费等待 —— 30 分钟内免费，超出部分计入超时；
3. 出场缓冲 —— 批准结束后 15 分钟内免费；
4. 超时部分 —— 不足 1 小时按 1 小时，¥5/小时；跨自然日按 ¥60/天封顶；
5. 页面展示“免费时间合计 / 超时计费时间 / 应付金额”，异常减免单列绿色说明。

## 异常场景处置（均有记录）

车牌录错（识别不符拦截，单位可入场前更正）、提前到达（宽限内外分别处理）、
跨夜停留（标记跨夜并按自然日封顶）、同车牌多邀请（门岗并列展示）、通行码转发（拒绝+记录）、
门禁离线（本地 `offline_queue` 排队，恢复后重放）、支付后闸机未开（重试只开闸不扣款）。

### 离线重放

门岗离线时事件以预分配 `event_id` 落入本地 `offline_queue`；恢复后 `replayOffline()` 重放：

- 成功项标记 `replayed`，重复触发不会二次执行；
- 邀请已使用/已取消/车牌不符的重放被拦截，标记 `failed` 并写一条 `OFFLINE_REPLAY_REJECTED` 处置记录。

命令行样例：`npm run demo`（构造“乙离线排队期间已在线入场，重放被拦截”的完整过程）。

## 模拟适配器（可替换为真实硬件/渠道）

- `src/adapters/camera.js`：生成保存到 `data/photos/` 的**车牌遮罩照片**（SVG，不保存原图）；
- `src/adapters/gate.js`：闸机开关，`_simulateGateFailOnce()` 制造一次故障；拒绝动作只记日志绝不开闸；
- `src/adapters/payment.js`：模拟支付，按 `request_id` 返回幂等结果与渠道流水号。

## 数据与存储

- SQLite：`data/park.db`（WAL），全部进出事件、回执、支付、异常、闸机日志、离线队列、审计；
- 遮罩照片：`data/photos/*.svg`；
- 主要表：`units / invitations / events（部分唯一索引保证一邀一入一出）/ exit_receipts /
  payments / exception_releases / gate_logs / offline_queue / audit_log`。

界面为白底、深灰文字、少量园区绿（`#0f5132`），异常理由一律完整文字展示。
